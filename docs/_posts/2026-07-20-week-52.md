# Week 52 – Integración de Modelo PyTorch Personalizado y Despliegue en CARLA con Behavior Metrics

## Trabajo realizado

- **Adaptación Arquitectónica del Modelo (PilotNet):** Se integró exitosamente la red neuronal convolucional entrenada a medida dentro de la suite Behavior Metrics. Se sustituyó la arquitectura base en el script de inferencia (`brain_pilotnet.py`) para alinearla con los pesos generados, configurando la red para entregar una salida única dedicada al control de dirección (steering).
- **Ajuste del Pipeline de Preprocesamiento de Imagen:** Para garantizar la compatibilidad tensorial y evitar colapsos en PyTorch durante la inferencia, se replicó exactamente el preprocesamiento utilizado en la fase de entrenamiento. Se implementó un recorte de imagen (Y: 250 a 500) para eliminar elementos innecesarios como el cielo y el capó del vehículo, seguido de un redimensionamiento al estándar de 200x66 píxeles.
- **Resolución de Dependencias y Políticas de Control:** Se solucionaron conflictos en el entorno virtual asociados a las librerías gráficas y de comunicación (realizando un *downgrade* a NumPy 1.x para habilitar la compatibilidad de `cv_bridge` con ROS 2 Humble). A nivel algorítmico, se intervino la política de control para desempaquetar correctamente las predicciones de la red, asignando un valor de aceleración constante (35% de potencia) para mantener la tracción mientras la IA controla el volante.
- **Configuración y Despliegue en Entorno de Alta Velocidad (Town04):** Se modificaron las jerarquías de configuración en `eval_pilotnet.yml` para migrar las pruebas al mapa Town04 (circuito de autopista). Se desactivó temporalmente la métrica de ruta ideal forzada (`UseTargetRoute: False`), solucionando los errores de *spawn* (apariciones fuera del mapa) y permitiendo al simulador asignar coordenadas seguras dinámicamente para iniciar la evaluación de conducción autónoma en tiempo real.
